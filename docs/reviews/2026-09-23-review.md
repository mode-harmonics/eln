## 结果

前次报告 R01–R09 的 10 条失败断言已全部关闭。扩展后的独立 HTTP 测试 **134/134 通过**，实际请求 Swagger 的 **99/99 个 method/path 操作**。没有更换技术栈、重建业务表、改变 decimal 字符串契约，也没有修改本地环境文件或部署。

接口操作覆盖不代表所有输入组合、仪器模板和科学公式都已穷尽验证。

## 修复内容

| 范围 | 本次落地行为 |
|---|---|
| R01 / R02 对象授权 | 统一项目、实验、附件、数据、设计、采购和工作流授权；角色权限与对象权限同时生效。项目修改、删除、成员管理和工作流重新分配限项目创建者。只读协作者、可见用户不能写入。 |
| R03 / R04 查询隔离 | 搜索、仪表盘统计、评论和历史使用相同可见范围。指定审核人可读取、审批对应实验，不获得其他实验或项目修改权限。 |
| R05 状态一致性 | 数据新增、单行、批量、删除、附件及配液操作统一草稿/已完成步骤限制；批量先校验全部目标，再原子提交。 |
| R06 / R07 删除完整性 | 有实验、流程或业务数据的项目返回 409；含数据、评论、附件或版本历史的实验返回 409。只允许删除空草稿，保留实验历史，不执行破坏性级联。 |
| R08 / R09 HTTP 参数 | UUID、分页及相关 DTO 在边界校验，非法参数返回 400；未预期异常返回通用 500，不向客户端披露数据库错误细节。 |
| 并发与审计 | 实验编辑、提交、批准、退回、归档统一事务和锁顺序；状态与版本历史同时提交。实际并发测试验证单一胜者及历史记录。 |
| 工作流 | 实例、分配、项目指针与通知在同一事务；模板引用保护与创建共用模板锁，禁止替换已引用模板的流程图；推进支持 expectedStepName，过期重试返回 409。 |
| 跨表写入 | 设计与采购生成、修改和删除保持事务一致；单文件和跨实验汇总导入同一事务，失败回滚新数据与新文件，提交后清理旧文件。 |
| 电池挑选 | 新增最小候选投影；仅挑选负责人可完成挑选及受控下游同步，无需授予其他实验写权限。同步只追加缺失占位，保留既有测量和行 ID，重复同步幂等。自动生成记录的 createdBy 不会绕过下游步骤授权。 |
| 前端失败与重试 | 子请求失败不伪装成空数据；项目已创建后重试流程复用项目 ID；挑选同步和步骤推进失败可重试，不显示虚假成功；库存/用户提交防重复，库存列表拒绝旧响应覆盖。 |
| 前端权限与可访问性 | 设计/采购独立加载，采购专属用户不被设计 403 阻断；按钮结合工步分配和项目所有者控制。补充操作名称、临时文件抽屉焦点循环/Escape/焦点恢复；窄屏项目表局部横向滚动。 |
| 汇总导入权限 | 只允许项目创建者执行；在创建任何新实验前校验全部目标步骤权限，阻断“空项目暂无实验”绕过，并保持失败时数据和文件不变。 |
| 配置和验证 | CLI 与运行时统一 DB_USER；生产 Compose 默认不执行演示 seed。CI 增加迁移、seed、数据库 E2E、独立 HTTP 测试和结果附件；前端加入可重复执行的 test 脚本。 |

首轮已修复的密码哈希泄露、临时文件跨用户访问、覆盖导入失败丢失原数据、搜索清空、错误登录反馈和详情路由状态串用均保留。

无新增 migration：这些问题属于应用层授权、事务和数据生命周期，现有表结构足以支持修复。没有批量清理既存孤立记录或重写生产业务数据。

## 保留的边界

- 权限全站列表目前读取轻量身份/成员列计算可见范围；单资源已按项目限制查询。大规模数据下仍需压测和 SQL 下推优化。
- 首次创建项目的响应完全丢失、或部分创建后刷新浏览器，尚无服务端幂等键/持久化恢复流程。已修复的是收到项目 ID 后的流程失败重试。
- 文件系统不能与 PostgreSQL 真正原子提交：正常失败路径有补偿，但进程硬退出或文件删除被拒绝仍可能遗留无引用文件，需要运维清理策略。
- 同步保留历史测量；重新分配电池不会自动删除旧测量。清理或转移历史记录需要单独业务决策。
- 尚未做长时间负载、完整移动端/键盘矩阵、所有页面故障注入、全部科学公式和仪器模板核验、生产部署与备份恢复演练。
- 静态 UI 审计仍有 40 条启发式提示，含原生控件决策与规则误报，不代表 40 个已确认功能缺陷或 WCAG 认证结果。没有为清零审计而改造界面。
