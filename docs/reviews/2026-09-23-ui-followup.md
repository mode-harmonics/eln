# 项目列表与工作流入口复核

前次 UI 审查没有覆盖项目列表与其他列表页的宽度对齐，也没有覆盖关闭创建弹窗后如何恢复未配置工作流的项目。因此，前次结论不能视为完整的逐页视觉验收。

## 本次确认的问题与处理

- 项目列表单独设置了 `760px` 表格最小宽度，而用户、角色列表使用共享 `Table` 的自适应宽度。已移除项目列表的额外固定宽度，保留共享 `TableWrapper` 在窄屏局部滚动。项目名和创建人过长时截断，项目名提供可键盘访问的详情链接。
- 创建向导在流程步骤为空时仍能创建项目，随后的工作流创建被跳过。现在步骤、可分配用户未加载或不可用时，创建操作不可提交，并显示重试或解释。
- 两次 HTTP 请求分别创建项目和工作流。工作流创建失败或用户关闭弹窗后会留下真实的未配置项目。列表和详情页现在为创建者提供继续配置入口，并沿用原项目 ID；归档项目不显示该操作。
- 详情页以前把工作流接口失败转成 `instance: null`，展示“未配置工作流”。现在请求失败显示错误和重试；只有接口成功且返回空实例时才展示未配置状态。
- 项目列表加载失败新增重试；未配置项目不再显示虚假的 0% 进度。移除侧栏没有目标页面的法律链接，并为移动端菜单按钮补充名称。

## 验证与边界

- 隔离 PostgreSQL 测试库有 80 个项目，其中 47 个没有工作流实例。真实 HTTP 请求验证了“空实例”和“已有实例”两种成功响应；默认模板有 8 个顶层步骤。
- 工作流逐步核查覆盖默认模板 16 个节点中的 14 个可执行叶节点：在隔离数据库中经真实 HTTP 请求逐个推进，最终 14/14 完成。11 个数据工步都生成了对应实验，数据读取接口均返回成功；设计、采购、电池挑选的页面路由也有契约测试。此项验证覆盖步骤流转及入口，不代表每张实验表单均已完成浏览器操作验收。
- 自定义工步映射内置实验类型时，原来首个工步与后续工步可能没有实验入口；现按 `builtInStep` 创建实验，并在首次激活时创建。自定义化成工步经真实 HTTP 验证能打开 ProcessData 数据接口。实验详情页现在以实例中的实际工步 ID 提交，只在工步处于进行中时允许写入或提交，接口失败提供重试。电池挑选页同样只在对应工步进行中开放操作。
- 测试组在挑选记录没有测试类型时不再把所有子工步跳过；若筛选后没有可执行子工步，工作流会结束该组并继续推进，避免卡死。
- 当前业务规则仍允许不填写实验数据就提交所有 14 个步骤，包括设计、采购和电池挑选。是否要求填写、需要哪些字段或数据量，尚无统一产品定义；本次没有擅自添加必填门槛。这是后续需要确定的业务规则，不应把本次流转测试误读为数据完整性验收。
- 前端 TypeScript、生产构建、8 个工作流契约测试、后端 196 个 Jest 用例与 `git diff --check` 通过。隔离数据库中的工作流 HTTP 矩阵通过。
- 当前会话没有可用的交互浏览器，因此项目列表对齐和弹窗点击路径尚未完成截图/键盘实测。之前的浏览器 smoke 也没有覆盖这些场景；不能据此宣称全站 UI 已验收。
